Introduction

SAP Customer Loyalty Management (CLM) is a cloud-based, multi-brand, multi-market loyalty platform built on UI5, intended to consolidate fragmented loyalty point solutions and experiential loyalty programs onto a single SAP enterprise platform — positioned to capture customers migrating from CRM 7 ahead of its 2027 end-of-life. The product reached general availability in October 2025 and releases on a two-week cadence, but is still in early implementation: provisioned partners and a small set of pilot customers exist, with no live production deployments yet. This DXR examined the live product across three sessions, focusing on the promotion specialist persona and the end-to-end promotion authoring flow (strategy, merchandise, offer, eligibility, budgeting, marketing details), the marketing program area, and the overview/workspace experience. The product shows clear instincts at the interaction layer — progressive disclosure, contextual prompts, an estimated promotion cost panel, and a thoughtfully decomposed wizard — but the foundation has not been stress-tested. Recurring weaknesses in language, status communication, data integrity safeguards, and onboarding indicate a UX maturity that is functionally promising yet structurally fragile, with meaningful adoption risk if shipped to enterprise users without remediation.

Strengths
  • The promotion authoring flow uses progressive disclosure to adapt subsequent steps to the chosen strategy (category, tactic, issuance type, offer type), reducing irrelevant fields for each promotion variant.
  • Inline contextual guidance is provided throughout strategy selection to help users understand each option as they configure a promotion.
  • The estimated promotion cost panel on the offer step gives specialists immediate, in-context feedback that builds confidence as they configure discounts.
  • Multi-language support for promotion name and description is built into the authoring flow, addressing a real need for global, multi-market customers.
  • The duplicate-promotion action on the promotion detail page directly supports a common real-world workflow where users clone an existing promotion and adjust only a few fields.
  • The overview page offers shortcut navigation cards to the main areas (programs, promotions, journeys, marketing calendar), giving users a consistent entry point into the system.
Areas of Improvement
  • Unclear and inconsistent language across the UI: Truncated button labels ("Starts on / Launch / Specific"), browser-translated warning dialogs mixed with English UI, ambiguous concepts like "program overlap" with values (no overlap / partial / full) whose meaning and desirability are not self-evident, and a mandatory "reason for launch" field with no explanation all create cognitive friction. Users cannot reliably interpret what they are selecting or why.
  • Weak safeguards around data integrity and destructive actions: There is no autosave during the multi-step promotion creation, navigating away loses all input (mitigated only by a warning), the budget field is informational only but not labeled as such, the offer issuance limit silently enforces a hard stop, and no validation exists for conflicting or overlapping promotions on the same products or audiences. For a system that controls real discounts and marketing spend, these gaps create material business risk.
  • Status, state, and process communication is underdeveloped: Draft promotions lack a visible status tag (only launched ones do), the confirmation dialog at draft creation implies completion when the promotion is not yet live, the planned approval workflow is absent so users can launch directly from draft, and informational counts (e.g., "0 of 10" offer slots, "1" guideline badge in red) are not explained. Users cannot easily tell what state an artifact is in, what will happen next, or what action is expected of them.
  • Lack of onboarding, guidance, and at-a-glance insight: There is no in-product onboarding (WalkMe is planned but not yet implemented), tooltips that previously existed have been removed, the overview page surfaces static "What's New" content and zeroed-out KPI cards with no personalization or AI-driven summaries, and the marketing calendar shows only program names with no campaign status, promotion counts, or pending tasks. Users are left to figure the system out on their own.
  • Inconsistent and fragile interaction patterns within the wizard and selection dialogs: The strategy step behaves like a vertical decision-tree wizard that invites exploration but penalizes it (changing an early step kicks the user back to the start), include/exclude product collections are independent rather than relationally constrained, exclusion uses the full catalog rather than the included set, default tabs in selection dialogs are not optimized for the most common scenarios, and the layout does not scale predictably as steps or list sizes grow.
Recommendations
  • Conduct an exhaustive UI language and content audit before launch: clarify program overlap terminology, fix truncated labels, ensure all UI strings render in a single language, explain badge counts and status indicators, and either remove or justify the mandatory launch-reason field. Pair this with a tooltip layer so the experience is usable without WalkMe.
  • Harden the data integrity layer: implement autosave for the promotion wizard, add validation for conflicting promotions and overlapping product/audience scopes, clarify in-context whether the budget enforces a stop or is informational only, and surface warnings before users can launch promotions that exceed defined limits.
  • Rework state and process communication: add an explicit draft-state tag, replace the post-creation confirmation modal with a pre-submission summary step that allows edits, prioritize implementing the approval workflow and task center so launches are gated appropriately, and make the primary call-to-action on the detail page reflect the next meaningful step (e.g., Launch).
  • Invest in onboarding and at-a-glance intelligence: ship the planned WalkMe guidance with a clear scope, redesign the overview and marketing calendar to expose campaign status, counts, pending tasks, and recent changes, and pilot AI-assisted insights and recommendations (e.g., performance summaries, conflict detection, suggested optimizations) to reduce the cognitive load on specialists.
  • Conduct user research with promotion and merchandising specialists and benchmark against the systems customers are migrating from: validate the wizard's decision-tree pattern, the include/exclude model, default tab choices, and information density on the calendar, ensuring the new experience meets or exceeds parity with current tools before asking customers to switch.
  • Engage SAP's design intent review process early and often for upcoming work (marketing program management, communication topics, merchandising) so foundational data-model and UX decisions are pressure-tested at the prototype stage rather than surfacing as UX debt post-launch.
